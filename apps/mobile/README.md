# mobile

Expo SDK 58 app (Expo Router, React Native 0.88) with the same spaces as
desktop and web: Day, Week and Projects on the time-of-day sky, with tasks,
focus, habits and Quick Add in glass windows over them. It works offline: every
command runs on the phone's own copy of the data, `time-core` over SQLite
through [`apps/mobile/native`](native), behind the same `Backend` port
as desktop ([`apps/shared/client/src/local`](../shared/client/src/local)). Sync with the server goes
through store's TypeScript driver. Rules come from
[`apps/shared/rules`](../shared/rules) and colours from
[`apps/shared/design`](../shared/design).

```bash
cp .env.example .env.local     # point at your server and OIDC provider
pnpm --dir native build:android   # native libraries (see below)
pnpm start                     # Expo dev server (needs a development build)
pnpm android / pnpm ios        # build and run a development build locally
pnpm compile && pnpm lint && pnpm test
```

Sign-in is OIDC Authorization Code + PKCE in the system browser with the
redirect `skkiltime://auth`; register that redirect with the provider. Tokens
are kept in the keychain (`expo-secure-store`). A sign-in whose token runs
out while offline stays signed in; only the provider refusing the refresh
token signs out.

## Native core

`@skkil-time/core-native` (in `native/`) is a Turbo Module generated by
uniffi-bindgen-react-native. Its static libraries are not committed, so build
them before a prebuild or `expo run:*`:

```bash
cd native
pnpm build:android    # cargo-ndk + NDK 30.0.14904198: arm64-v8a, x86_64
pnpm build:ios        # macOS with Xcode: device and simulator xcframework
pnpm check:ios        # on Linux: cargo check of the iOS targets only
```

To run on an Android emulator or phone, add it once with `skkil device init`
and start it with `skkil device up <name>` from the repo root. That runs
`scripts/run-android.sh`: it builds the native core, installs a debug build
for the device's ABI, forwards the API, issuer and store ports, and serves
Metro on 8088 because the server's management port takes 8081.

The database is `time.db` in the app's document directory. The engine has
its own thread: commands are async; store's sync calls are synchronous by
the driver's contract and touch one page at a time.

## Sync

`src/core/sync/` drives `@skkil/store-client`, linked from the store checkout
next to this repo (`../store` at `STORE_VERSION`, with `pnpm install && pnpm
build` run in `modules/client-ts`). Metro watches that folder
(`metro.config.js`).

- Once signed in, the replica is bound to the account's store scope. If it
  holds another account's data, the app asks whether to keep it (upload it
  into the new account) or use the account's data instead.
- A sync token comes from `POST /api/v1/sync/token`; pushes carry the
  sign-in's bearer token; the Pokes stream uses `expo/fetch`, which can
  stream.
- Sync runs while the app is in the foreground, restarts when it comes back
  or the network returns, and pushes shortly after each change. Pulled
  changes refresh the screens.
- Settings → Sync shows changes waiting, the last sync, Sync now and the
  changes the server refused. Signing out removes this device's copy of the
  account, after a warning when changes haven't synced.

## Code layout

```
app/                    Expo Router routes only: each file re-exports a screen
src/
├── core/               app-wide services, no UI
│   ├── api/            server client (sync tokens, account, push), query client
│   ├── auth/           OIDC sign-in, the session provider, sign-out
│   ├── local/          the replica, its Backend and device-only commands
│   ├── sync/           store driver, account binding, sync status
│   ├── notifications/  push registration and reminder taps
│   └── config.ts       EXPO_PUBLIC_* settings
├── features/<name>/    one folder per feature: *Screen.tsx, components/, hooks.ts
│                       (shell, today = Day, week, projects, tasks, focus,
│                       habits, account)
├── ui/                 theme, Sky, Screen, Window, surfaces, Group, Check,
│                       loading/empty/error states, notices
└── types/
```

`core` and `ui` never import from `features`; a feature may use `core`, `ui`
and another feature's components (Today shows task rows).

## Release

```bash
eas build --profile production --platform all
eas submit --profile production
```

Set `EAS_PROJECT_ID` and the `EXPO_PUBLIC_*` variables in the EAS environment.
EAS builds need the native libraries too: build them before `eas build
--local`, or add the Rust toolchain to the EAS image. Icons come from
`assets/icon.svg` at the repo root: `skkil assets generate` renders the app
icon, splash and favicon, and `scripts/android-icons.sh` the Android
adaptive layers. `EXPO_PUBLIC_LEGAL_URL` points Settings at the privacy
policy and terms.
