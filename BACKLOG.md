# BACKLOG: server, web and mobile

Started 2026-11-08. Goal: release-ready `apps/server` (Spring Boot 4, Kotlin),
`apps/web` (Vite + React, full desktop parity) and `apps/mobile` (Expo React
Native), with shared TypeScript code in `apps/shared/*` so a change made once
reaches every app. Sync is out of scope (it comes from `../store`).

Each item is one commit. Check it off when it lands.

## Decisions

- **One UI for desktop and web.** The desktop frontend moves to
  `apps/shared/app`. It reaches its backend only through a `Backend` port with
  the exact shape of the Tauri `commands`; desktop plugs in Tauri, web plugs in
  HTTP. Platform-only behaviour (windows, files, hotkeys) goes through a
  `Platform` port.
- **The Rust bindings are the contract.** `apps/shared/contract/bindings.ts` is
  generated from Rust. The server's OpenAPI types are generated into
  `apps/shared/api`, and the web HTTP backend must `satisfies Backend`, so any
  drift between Rust, Kotlin and TypeScript fails `tsc`.
- **Numeric ids.** The server uses `bigint` identity ids so `Id = number` holds
  in every app. Client-generated ids arrive with sync.
- **Timestamps are epoch seconds, dates are `YYYY-MM-DD`**, as on desktop.
  "Today" on the server comes from the `X-Time-Zone` header (IANA), falling
  back to the user's saved zone.
- **Auth is swappable.** The server is an OAuth2 resource server only (issuer
  and audience from config, JWKS validation); `(issuer, subject)` maps to an
  internal user id. Clients use OIDC Authorization Code + PKCE through
  `apps/shared/auth`. Auth0 today, the skkil auth service later: a config
  change.
- **Persistence:** Postgres, Flyway, Spring `JdbcClient` with explicit SQL
  (a direct port of the Rust queries), every row scoped by `user_id`.
- **Errors:** RFC 9457 problem details with `kind` (`invalid`, `notFound`,
  `database`, `unauthorized`), mapped back to the desktop `Error` shape.
